# WZDQ App — локальная версия

Запуск из корня DJ_AI_BOT:

```bash
bash scripts/run_miniapp.sh
```

Открыть: **http://localhost:8080/app/**

Если порт занят:

```bash
MINIAPP_PORT=8081 bash scripts/run_miniapp.sh
```

Открыть: http://localhost:8081/app/

## Что работает

- Раздел «Пул музыки»: весь сохранённый каталог, поиск по названию и исполнителю, фильтры по жанру, BPM и Camelot, постраничный просмотр.
- Переход из пула к генератору с выбранным жанром, если он поддерживается генератором (Electronic / House / Rap).
- Каталог Electronic / House / Rap из существующего бота.
- Выбор 30 / 60 минут и BPM-кластера для Rap.
- Генерация существующим алгоритмом BPM + Camelot + энергия.
- Просмотр порядка, исполнителей, BPM, тональностей и длительности.
- Автоматическая история сетов, избранное и повторная генерация без треков предыдущего сета.
- Скачивание текстового треклиста.
- Адаптивный интерфейс для компьютера и телефона.

## Изоляция

Сервер слушает только `127.0.0.1`. Локальный режим дополнительно проверяет адрес клиента и Host. Это не публичный сайт и не подключённое к Telegram Mini App.

При первом запуске `scripts/prepare_miniapp_db.py` читает только таблицу `tracks` из `dj_ai_bot.db` и копирует её в **`dj_ai_bot_miniapp.db`**. Исходная база не меняется. Все сеты и избранное записываются в таблицу `miniapp_sets` отдельной базы. При повторных запусках история сохраняется. Если исходной базы нет, приложение запускается с пустым каталогом.

Команда запуска устанавливает `MINIAPP_LOCAL=true` и отдельный `DATABASE_URL`. `.env` используется для существующих настроек проекта; секреты в браузер не передаются. Можно выбрать другой файл через `APP_ENV_FILE`.

Бот, polling, сканирование канала и деплой не запускаются. Отправка в Telegram заблокирована в локальном режиме. В production-файлы запуска, меню бота, systemd и GitHub Actions приложение не подключено.

Для локального интерфейса не нужны npm, Node или подключение к внешним шрифтам. Manrope хранится в `web/fonts` вместе с лицензией OFL. Запуск использует имеющийся Python `venv` и зависимости из `requirements.txt`.

## Проверки

```bash
venv/bin/python -m pytest tests -q -p no:cacheprovider
```

Тесты Mini App создают временную базу и отдельный HTTP-сервер: проверяют генерацию, фильтры, сохранение, повторный сет, избранное, запрет отправки, ограничения локального доступа и валидацию подписи Telegram. Тесты не обращаются к Telegram и не пишут в базы бота.

Текущая локальная версия имеет один общий локальный профиль DJ. Аудиоплеер и скачивание самих аудиофайлов пока не реализованы; экспортируется треклист. Подключение к настоящему Telegram Mini App — отдельный следующий этап с публичным HTTPS, проверкой подписки и кнопкой запуска.

Раздел пула читает сохранённую локальную копию каталога, включая жанры, которые пока не поддерживаются генератором. Подключение к Telegram и обновление из закрытого канала при запуске приложения не выполняются. Наличие файлов сессии не подтверждает действующую авторизацию; проверка сессии и синхронизация канала выполняются отдельно.

## Показать интерфейс друзьям

Запустить: `bash scripts/share_miniapp.sh`.

Скрипт запускает отдельный сервер на `127.0.0.1:8090` и SSH-туннель через localhost.run. Отправь друзьям HTTPS-адрес `https://….lhr.life`, который появится в терминале. Ничего устанавливать не нужно: используется системный SSH. Для остановки нажми Ctrl+C в этом терминале.

Это отдельная демонстрация интерфейса, без подключения к базе, настройкам и боту. Сеты состоят из демонстрационных треков; генерация примеров и избранное работают в браузере посетителя, без записи на сервер. После перезагрузки страницы демонстрационная история исчезнет.

Ссылка временная: компьютер должен оставаться включённым и подключённым к интернету, а сервер демонстрации и SSH-туннель — работать. Бесплатный сервис может менять адрес или разрывать соединение; повторный запуск выдаст новую ссылку. Подробности: https://localhost.run/docs/forever-free/.

Production и VPS не используются. Локальное приложение с настоящим каталогом на порту 8080 в туннель не попадает.

## Открыть внутри Telegram с этого компьютера

```bash
bash scripts/run_telegram_miniapp.sh
```

Запуск проверяет токен бота и доступ к пулу, поднимает отдельный сервер на `127.0.0.1:8082`, создаёт временный HTTPS-туннель и устанавливает общую кнопку «Открыть приложение» для пользователей бота. Для администраторов из `ADMIN_USER_IDS`, состоящих в пуле, персональная кнопка обновляется на тот же адрес. Вход в приложение разрешён только участникам пула. Подключается Telegram WebApp SDK; сервер проверяет подпись Telegram и членство в канале. Каталог, история и генерация используют отдельную `dj_ai_bot_miniapp.db`. Кнопка «Получить треки в чат» отправляет аудиофайлы из облака через бота в порядке сета и показывает прогресс. Если облачное хранилище не настроено, используется существующая доставка через Telegram-сессию. Экспорт текстового треклиста в обычном локальном браузере сохраняется. Сканирование канала и polling бота не запускаются.

Открой бота по ссылке, которую напечатает запуск, и нажми кнопку рядом со строкой ввода. Если меню не обновилось сразу, закрой и снова открой чат. Обычная HTTPS-ссылка вне Telegram не даёт доступа к каталогу.

Компьютер должен оставаться включённым, а команда — работающей. Ctrl+C завершает сервер и туннель и восстанавливает прежнее меню для этих чатов. При аварийном отключении компьютера старый адрес может остаться в кнопке — повторный запуск заменит его. Для тестового бота можно задать `APP_ENV_FILE=.env.dev`; другой порт — `MINIAPP_TELEGRAM_PORT=8083`.

Запуск проверяет публичную страницу каждые 15 секунд, включая случай HTTP 200 с текстом `no tunnel`. После двух неудачных проверок или разрыва SSH туннель переподключается и адрес кнопки обновляется. Смена адреса, объявленная сервисом в существующем SSH-соединении, тоже обновляет кнопку. Если окно Mini App уже открыто со старым адресом, закрой его, заново открой чат и нажми кнопку ещё раз.

### Тестирование друзьями — участниками пула

Отправь друзьям ссылку на бота, которую выводит запуск (сейчас `https://t.me/wzdqBOT`). Нужно открыть личный чат, нажать «Начать», затем кнопку меню «Открыть приложение». Адрес `localhost` друзьям отправлять не нужно.

Компьютер владельца и процесс запуска должны работать. При смене туннеля обновляется и общая кнопка. Сеты и избранное разделены по Telegram user ID; подписка проверяется сервером при каждом API-запросе. При остановке восстанавливаются и общее меню, и сохранённые персональные меню администраторов.

### Туннель для совместного тестирования

По умолчанию `run_telegram_miniapp.sh` использует localhost.run через системный SSH. На проверенном адресе приложение открывается сразу без страницы подтверждения. Скрипт отслеживает смену адреса и доступность HTTP, обновляет общую кнопку и персональные кнопки администраторов. При смене адреса старое окно Mini App нужно закрыть и открыть заново через бота.

Pinggy больше не используется по умолчанию: в Telegram экран `Enter site` мог оставаться даже после нажатия. Проверка туннеля теперь использует браузерный User-Agent и проверяет страницу приложения, защищённый GET каталога и защищённый POST поиска аудио. Служебная страница с HTTP 200 не считается рабочим приложением. Сервер продолжает проверять подпись Telegram и подписку на пул.

Pinggy можно выбрать через `MINIAPP_TUNNEL_PROVIDER=pinggy bash scripts/run_telegram_miniapp.sh`, но его экран подтверждения может мешать входу из Telegram. Бесплатный localhost.run также меняет адреса: автоматическое обновление кнопки не исправляет уже открытые окна со старым адресом.

Контроль запуска также проверяет общую кнопку меню и известные персональные кнопки каждые 15 секунд и восстанавливает актуальный адрес, если меню было сброшено или изменилось.

### Постоянный внешний адрес, например Tailscale Funnel

21 октября Tailscale установлен владельцем и подключён. Funnel направлен на `127.0.0.1:8082`; публичная страница приложения вернула 200, защищённые GET и POST без Telegram-подписи — 401. Проверка не запускает поиск или скачивание. Текущий адрес сохранён в игнорируемом `.sessions/miniapp-public-origin`: обычный `bash scripts/run_telegram_miniapp.sh` теперь использует его без SSH-туннеля. Явные переменные окружения позволяют переопределить выбор.

Обновление и чтение меню используют поддерживаемый Bot API GET с параметрами: JSON POST возвращал успех, но повторное чтение общей кнопки оставалось со старым адресом. После GET проверены и общая, и персональная кнопки — обе возвращают адрес Funnel.

После установки Tailscale, входа владельца и разрешения Funnel направить только локальный порт API:

```bash
tailscale funnel --bg http://127.0.0.1:8082
```

Полученный HTTPS-адрес без `/app/` передать запуску вместо временного SSH-туннеля (старый запуск сначала завершить; активные задания должны быть закончены):

```bash
MINIAPP_TUNNEL_PROVIDER=external MINIAPP_PUBLIC_ORIGIN=https://имя-устройства.имя-сети.ts.net bash scripts/run_telegram_miniapp.sh
```

Скрипт проверяет страницу и защищённые GET/POST до замены кнопок. При недоступности ждёт восстановления того же адреса. Funnel управляется отдельно и не останавливается вместе с API; выключение отдельной командой `tailscale funnel --https=443 off`. Mac, интернет, Tailscale и API должны продолжать работать. Документация: https://tailscale.com/docs/features/tailscale-funnel.

## YouTube → треки

В Mini App есть отдельная вкладка YouTube и карточка входа на главной. Ссылка вводится на странице, найденные композиции и прогресс обновляются каждые 2,5 секунды. Можно перейти в другие разделы: анализ продолжится, пока работает локальный API. История и результаты сохраняются в SQLite отдельно для каждого пользователя. После перезапуска незавершённый разбор можно запустить повторно.

Используется существующий анализатор из соседнего `/Users/admin/Documents/youtube_setlist_bot`, через его `.venv-shazam/bin/python`. Исходники отдельного бота не меняются, polling не запускается. Для другого расположения задай `YOUTUBE_SETLIST_PROJECT`; нужны готовое окружение анализатора, его `.env` и `ffmpeg`. Сначала проверяются опубликованные треклисты, затем при необходимости анализируется аудио. В полном отчёте указаны источники и ограничения. Точность и полнота распознавания не гарантируются.

Один API-процесс выполняет один разбор одновременно. Ограничения длительности и частоты фрагментов берутся из настроек анализатора (сейчас до 180 минут, шаг 30 секунд). Временное аудио удаляется анализатором при завершении или отмене. Результат можно скачать как TXT, а в Telegram — отправить текстовый файл в чат кнопкой «Треклист в чат». Найденные аудиофайлы этот раздел не скачивает.

Проверка: `venv/bin/python -m pytest tests/test_miniapp.py tests/test_miniapp_youtube.py -q`. Тестовый анализатор изолирован во временном каталоге: проверяются появление трека до завершения, итоговый список, история, приватность и проверка ссылок, без сетевых запросов к YouTube и Telegram.

## Профиль и рейтинг

Профиль показывает полную статистику из базы, а не только последние 100 сетов. Рейтинг учитывает каждую успешно сохранённую генерацию Mini App за всё время. Повторная отправка или скачивание треков рейтинг не меняют. Одинаковое число генераций даёт одинаковое место (1, 1, 3). Показаны топ-20 и собственное место, если оно за пределами списка. Локальный профиль с ID 0 исключён из рейтинга.

Имена участников сохраняются из проверенных данных Telegram при открытии приложения и генерации. Для старых генераций имя станет видно после следующего входа участника; до этого выводится «Участник пула». В ответ рейтинга не входят Telegram ID, username или содержимое чужих сетов. Доступ к профилю и рейтингу требует той же авторизации и подписки на пул.

В YouTube теперь всегда запускается анализ аудио после опубликованных треклистов. Локальный `scripts/miniapp_full_analysis.py` использует существующие функции отдельного анализатора без изменения его исходников. Найденные в публикациях треки появляются до скачивания аудио; затем добавляются новые совпадения. При ограничении Shazam или ошибке загрузки сохраняется найденная часть и показывается причина остановки. Анимация поиска не заменяет реальный прогресс: проценты считаются только по проверенным фрагментам.

## Знания

В боковом и мобильном меню добавлена видеотека «Знания». Пока каталог пуст; вымышленных уроков нет. Названия, описания и ссылки хранятся в `assets/knowledge/catalog.json` в массиве `videos`. Для каждой записи нужны уникальные `id`, `title`, HTTPS `url`; необязательны `description`, `category` (по умолчанию «Уроки») и `thumbnail_url`. Изменение каталога подхватывается API без перезапуска; в открытом приложении нужно обновить страницу.

Поиск и категории показываются после добавления первого ролика. YouTube открывается во встроенном плеере по нажатию, MP4/WebM/M4V по прямой HTTPS-ссылке — в видеоплеере, остальные ссылки открываются в источнике. При уходе из раздела воспроизведение останавливается. Метаданные доступны только через авторизованный `/miniapp-api/knowledge`; права доступа к внешнему видео определяет его источник. Каталог предназначен для редактирования владельцем проекта; загрузки файлов из браузера и публичного редактирования нет.

### Загрузка видео владельцем

В «Знаниях» владелец может нажать «Добавить видео», ввести название и выбрать MP4 (H.264) или WebM до 500 МБ. Проверка владельца выполняется на сервере после проверки подписи Telegram и подписки. Сейчас владелец определяется единственным `ADMIN_USER_IDS`; если администраторов несколько, загрузка отключается до настройки отдельного владельца. Локальный профиль DJ и остальные участники загружать видео не могут.

Файлы сохраняются в `.data/knowledge/videos` вне публичного `web/`, записи — в таблице `miniapp_knowledge_videos`. Оба каталога используют ту же локальную копию базы; видео не отправляются в облако. Проверяются действительный формат, видеодорожка и длительность через ffprobe. Обложка создаётся через ffmpeg. Во время загрузки виден процент, доступна отмена; незавершённые и отклонённые файлы удаляются.

Просмотр доступен участникам через подписанные ссылки на два часа; поддерживается HTTP Range для перемотки. Для обновления ссылок достаточно заново открыть раздел. Ссылку, полученную участником, можно использовать до её истечения; это временный доступ к конкретному файлу. Для переезда нужно перенести и SQLite, и каталог `.data/knowledge/videos`.

HEVC/H.265 в MP4/MOV теперь принимается: до публикации видео автоматически преобразуется в H.264/AAC MP4 с faststart. Исходный файл пользователя не меняется; временная загруженная копия удаляется после подготовки. Подготовка ограничена 10 минутами, 500 МБ результата и резервом свободного места; при ошибке незавершённый результат не публикуется и удаляется. Проверено на пользовательском 720×1280 HEVC/AAC, 59,27 секунды: полученный H.264 воспроизводится в Chromium с той же длительностью и размерами.

## Аудиофайлы найденных в сете треков

Каждое новое совпадение сразу поступает в очередь поиска аудио; одна загрузка идёт параллельно распознаванию сета. Используется `find_audio` отдельного YouTube-бота: сверка исполнителя, названия и версии, сравнение источников и проверка аудио через ffprobe. Статусы: очередь, поиск, скачивание, готово, не найдено, ошибка. Для старых результатов доступна кнопка «Найти и скачать аудио» без повторного распознавания видео.

Готовый MP3 можно скачать из Mini App на устройство; сообщения и аудио в чат автоматически не отправляются. В поддерживаемом Telegram используется `downloadFile`, иначе открывается ссылка на скачивание. Реальная работа системного окна Telegram зависит от версии клиента; браузерный путь проверяется отдельно. Параметры: https://core.telegram.org/bots/webapps#downloadfileparams.

Аудио хранится в `.data/youtube-audio/<job_id>/` до 24 часов; старые каталоги очищаются при старте API и нового анализа. Максимум 45 МБ на файл, 1 ГБ на сет, резерв диска 1 ГБ. После отмены уже готовые файлы сохраняются до истечения срока; незавершённые рабочие каталоги удаляются. Старые метаданные отмечаются как истёкшие, если файла больше нет.

Только владелец результата может запросить ссылку на аудио. Подписанная ссылка действует 10 минут, поддерживает HEAD/Range и может использоваться получателем до истечения срока. Файлы вне `web/`; доступ к чужому job_id не выдаёт ссылку. Битрейт перекодированного MP3 не выдаётся за качество источника: в интерфейсе показывается формат и измеренный битрейт исходного потока, когда он известен.

### Ошибка Load failed на действиях Mini App

API-запросы и загрузка видео отправляют `X-Pinggy-No-Screen: 1`, чтобы служебная страница Pinggy не подменяла JSON. Для POST без параметров передаётся явный `{}`. Полученный HTML или обрыв fetch теперь дают сообщение о переподключении, а не успешный ответ или необработанное Load failed. Проверено через текущий публичный HTTPS-адрес в Chromium: запрос кнопки доходит до API; для проверки использован несуществующий job_id, без запуска скачивания. Заголовок документирован: https://pinggy.io/docs/http_tunnels/screening/.
