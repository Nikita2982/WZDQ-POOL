# Сводка изменений за последние 2-3 часа

## 1. Исправили разметку жанров в канале

- Улучшили определение границ секций по хэштегам в обычных текстовых сообщениях.
- Исправили кейс, когда новый блок начинался не отдельным сообщением `#tag`, а текстом вида `Soundcloud selected #lossless`.
- Убрали ложное срабатывание, когда хэштег находится в подписи самого аудиофайла.

## 2. Почистили ошибочные треки в базе

- Удалили ошибочные записи из `electronic`, включая `Jamaican`.
- Проверили `jet set x alkogol` и установили, что он был записан в `electronic` не по своему хэштегу, а по активной секции на момент старого скана.
- Для точечной чистки добавили служебный скрипт удаления по жанру и названию.

## 3. Исправили названия треков в выдаче бота

- Убрали технические цифровые префиксы из отображаемых названий при отправке треков в Telegram.
- Это исправляет кейсы вида `1083_...`, `1077_...`, `1256_...` в карточке аудио.

## 4. Доработали повторную генерацию

- Сообщение `Генерация завершена` больше не удаляется перед повторной генерацией.
- Перед повторной генерацией добавлено промежуточное сообщение.
- После нажатия `Повторить генерацию` появился отдельный выбор тайминга: `30` или `60` минут.
- Память предыдущих треков сохраняется внутри repeat-сценария.

## 5. Исправили сброс памяти повторов

- Если пользователь уходит назад к выбору жанра, история исключенных треков очищается.
- То же самое происходит после `/start`.
- Исключение дублей работает только внутри реального сценария `Повторить генерацию`.

## 6. Доработали генератор плейлистов

- Добавили сообщение: если после исключения дублей треков получилось меньше, бот явно сообщает, что треков меньше, но они уникальны.
- Для repeat-сценария добавили более строгую логику по `key` с одним допустимым послаблением за генерацию, если иначе подбор обрывается.
- Потом ограничили эту строгую `key`-логику только repeat-сценарием, чтобы обычная новая генерация не урезалась.

## 7. Выкатили изменения на сервер

- Сделали несколько коммитов, `git push`, `git pull`.
- Перезапускали `wzdq-bot` через `systemctl`.
- Проверяли, что сервис после рестарта поднимается и продолжает polling и live monitor без ошибок запуска.
